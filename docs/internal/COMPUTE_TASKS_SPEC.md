# Meridian Compute tasks, phase 1: wire and behaviour specification

Status: **binding** for phase 1. Three engineers implement it in parallel:

| Owner | Repo | Parts |
|---|---|---|
| **CP** (control plane) | `Meridian` | `meridian_control/`: §2, §3, §4.2, §4.3 (server side), the CP rows of §9, the e2e test of §11 |
| **NODE** (node agent and helper) | `meridian-node` | §4 (client side), §5. The self-contained copy is `meridian-node/docs/COMPUTE_TASKS_NODE.md` and `contracts/v1/` |
| **SDK** (Python SDK, CLI, runner) | `Meridian` `sdk/python/` | §6, §7, §8, §10 |

Where this document and `COMPUTE_TASKS_NODE.md` disagree, this document wins and the node document is fixed.

Keywords: MUST, MUST NOT, SHOULD are as in RFC 2119. "CP" = meridian-control. "Agent" = the non-root `meridian-node run` process. "Helper" = the root `meridian-node helper` daemon. "Runner" = `meridian_runner.py` inside the container.

Every value a user supplies is validated at the first boundary that receives it and is then treated strictly as data. It never becomes part of a shell command, SQL text, a filesystem path, a template, or an input to a control-plane decision (placement, quota, billing or visibility). Paths are built only from server-generated ids and validated digests. The CP, agent and helper never parse or deserialize a bundle's files, a payload or a result. To them these are opaque bytes with a digest and a size. (Tar extraction on the node parses the archive *format* to lay out files; it never interprets file contents.)

## 1. Vocabulary and lifecycle

### 1.1 Terms

| Term | Meaning |
|---|---|
| **Task** | A Python function call that runs remotely. It is stored as a `compute_jobs` row with `kind = "task"`, plus one `compute_tasks` row (§3.3). Its public id is the job id (`job_…`). |
| **Run** | The SDK's handle to one task (`Run.id` is the job id). |
| **Bundle** | A deterministic `tar.gz` of the user's source tree plus the runner (§7.1). It is content-addressed: `sha256` of the exact compressed bytes. |
| **Payload** | `args.json`, the JSON-encoded call arguments (§6.5). Content-addressed. |
| **Result** | The bytes of `result.json` or `error.json` that the container wrote, uploaded by the node. Its `kind` is `result` or `error`. |
| **Replica** | A task always has exactly one replica (rank 0), held in `compute_job_replicas`. |
| **Stage** | Node-reported progress within a replica phase (§4.4). |

### 1.2 States

A task's client-facing `state` is derived from the existing job status. No new job statuses are introduced.

| Task `state` | `compute_jobs.status` | Replica `phase` (node) | Typical `stage` | Who moves it there |
|---|---|---|---|---|
| `queued` | `queued` | (no replica row) | — | CP at submit, or `_place` finding no capacity |
| `starting` | `scheduled` | `Pending`, then `Starting` | `fetching`, `launching` | CP `_place` creates the replica; the node reports `Starting` |
| `running` | `running` | `Running` | `running`, `collecting`, `uploading` | node reports `Running`; CP `_settle` |
| `succeeded` | `succeeded` | `Succeeded` **and** stored result kind `result` | `done` | CP `_settle` (§1.4) |
| `failed` | `failed` | `Failed`, or `Succeeded` without a `result`-kind result, or CP-detected failure | `done` | CP `_settle` / deadline / node loss |
| `cancelled` | `cancelled` | `Cancelled` | `done` | user cancel (CP), then the node stops the container |

`outcome` (in the task view, §2.6) is `null` until the task is terminal, and then one of:

| `outcome` | When |
|---|---|
| `result` | `succeeded` |
| `error` | `failed`, with a stored result of kind `error` (the function raised, or the runner reported a protocol/import/argument/encoding error) |
| `infra` | `failed` without a stored `error` result. `failure.reason` says why (§1.6) |
| `cancelled` | `cancelled` |

### 1.3 Transitions and clocks

The CP's clock is authoritative for every deadline. Node-reported times are clamped exactly as `_ingest` does today (into `[scheduled_at, received]`). The node's clock decides only the node-side run timeout, and a node can only end a task early, never keep it alive.

| Transition | Actor | Trigger | Clock |
|---|---|---|---|
| submit → `queued` | CP | `POST /tasks` accepted | CP |
| `queued` → `starting` | CP `_place` | a node of the workspace that advertises task protocol 1 has capacity (§4.3) | CP; sets `scheduled_at` |
| `Pending` → `Starting` | node | the agent begins fetching the bundle | node time clamped |
| `Starting` → `Running` | node | `docker run -d` returned a container id | node time clamped |
| (container exits) → collect → upload → terminal phase | node | §5.6. The upload MUST complete before the terminal phase is reported | node |
| `running` → `succeeded`/`failed` | CP `_settle` | the replica phase is terminal (§1.4) | CP |
| any → `failed` (StartDeadline) | CP `_settle` | replica `Pending`/`Starting` for more than `job_start_deadline_seconds` (default 1800) since `scheduled_at` | CP |
| any → `failed` (Timeout) | node, then CP | node: container running longer than the task's `timeout_seconds` → stop, `Failed/Timeout`. CP backstop: §1.5 | node / CP |
| any → `failed` (NodeLost) | CP `_settle` | the node is silent longer than `node_lost_seconds` (default 300) | CP |
| any → `cancelled` | CP `cancel_job` | user cancel; the node then stops the container (`desired_phase: Stopped`) | CP |

### 1.4 Settling a task (CP `_settle` change)

`_settle` keeps its current logic for `job` and `service`. For `kind == "task"`, once the replica phase is terminal:

1. Replica `Cancelled` and the job is not yet terminal → job `failed`, with `failure_reason` = the replica reason (for example `Cancelled` from an operator stopping the container by hand). A user cancel has already made the job `cancelled` through `cancel_job`.
2. Replica `Succeeded` **and** `compute_tasks.result_kind == "result"` → job `succeeded`.
3. `result_kind == "error"` (whatever the phase) → job `failed`, `failure_reason = ""`, message `"the task raised an error; fetch its result for details"`. The CP never reads the error's contents.
4. Otherwise → job `failed`, `failure_reason` = the replica `reason` if it matches `^[A-Za-z]{1,64}$`, else `"Unknown"`. Special case: reason `ResultMissing` with `exit_code == 137` → `failure_reason = "Killed"`. If the replica reported `Succeeded` with no stored result → `failure_reason = "ResultMissing"`.

The CP never waits for a late upload. The node uploads before it reports a terminal phase (§5.6), so a terminal report without a stored result means there is none.

### 1.5 Timeouts

| Timeout | Value | Enforced by | Measured from |
|---|---|---|---|
| Start deadline | `job_start_deadline_seconds` (1800, existing) | CP | `scheduled_at`. Covers the bundle fetch and the image pull |
| Run timeout | the task's `timeout_seconds` (1 to 2,592,000, required) | node, precisely | container start (`Running`) |
| CP backstop | `compute_jobs.timeout_seconds = task timeout + job_start_deadline_seconds + TASK_DEADLINE_SLACK_SECONDS` | CP `_settle` (existing rule) | `job.started_at` (first non-`Pending` phase) |
| Client wait | `Run.result(timeout=)`; `None` = forever | SDK | local monotonic clock. Raises `WaitTimeout`; the task keeps running |

`compute_tasks.timeout_seconds` holds the user's timeout. `_replica_spec` MUST send `compute_tasks.timeout_seconds` (not `compute_jobs.timeout_seconds`) as the snapshot `timeout_seconds` for a task.

### 1.6 Failure reasons (`failure.reason`)

These are string codes. The SDK maps known codes to exception classes (§7.6) and unknown codes to `InfraError`.

| Reason | Set by | Meaning |
|---|---|---|
| `StartDeadline` | CP | not running within the start deadline |
| `Timeout` | node (or CP backstop) | exceeded `timeout_seconds` |
| `NodeLost` | CP | the node stopped reporting |
| `Killed` | CP | exit 137 with no result (out of memory or SIGKILL) |
| `ResultMissing` | node / CP | the container exited without a valid result or error file |
| `ResultInvalid` | node | the out directory held something other than exactly one regular file named `result.json` or `error.json` |
| `ResultTooLarge` | node | the file exceeded `MAX_RESULT_BYTES` |
| `ResultUploadRejected` | node | the CP refused the upload with a non-retryable error other than `TASK_FINISHED` |
| `BundleFetchFailed` | node | the bundle or payload could not be downloaded after retries (§5.3) |
| `BundleDigestMismatch` | node | the downloaded bundle's sha256 or size differs from the snapshot |
| `PayloadDigestMismatch` | node | the same, for the payload |
| `UnsafeBundle` | node | safe extraction refused the archive (§5.4) |
| `NodeDiskFull` | node | less than 512 MiB free under the state directory before fetching |
| `PolicyDenied`, `InvalidSpec`, `LaunchFailed`, `LaunchUncertain`, `SpecChanged`, `ContainerLost`, `LocalAdmissionRejected` | node | existing job reasons, unchanged |
| `Unknown` | CP | the node sent a reason outside `^[A-Za-z]{1,64}$` |

### 1.7 Node loss, CP restart and agent restart

| Event | Behaviour |
|---|---|
| **Node lost** (silent > `node_lost_seconds`) | Existing `_settle`: replica `Failed/NodeLost` → task `failed`, `infra`, `NodeLost`. Late uploads are refused with `409 TASK_FINISHED`. No retry in phase 1 (tasks are never run twice). |
| **CP restart** | All state is in the DB and the blob store. In-flight client uploads fail; the SDK retries them (PUT is idempotent by digest). In-flight node uploads fail; the agent retries on its next tick. Partial upload files in `<store>/tmp/` are removed by GC (§3.4). The tick resumes. No task is re-run. |
| **Agent restart before launch** (stage `fetching`) | No journal `launch_job` entry exists. The agent deletes `<state>/tasks/<job_key>/` and fetches again. |
| **Agent restart after launch** | Existing journal adoption (`COMMITTED`/`STARTED` plus ownership marker). An exited container is collected (§5.6). The out tmpfs and the container survive an agent restart, so the result is not lost. |
| **Agent restart after upload, before the terminal report** | It collects again (the out tmpfs is intact) and uploads again. The CP answers `200` for the same digest (§4.2). Then it reports. |
| **Helper restart** | The helper journal and the out tmpfs mounts persist. Its startup sweep (§5.8) unmounts only the out directories that have no owned container. |
| **Host reboot** | The tmpfs contents are lost and the container is gone → `ContainerLost` or `ResultMissing` → task `failed` (infra). |

## 2. Control-plane API (client-facing)

### 2.1 Common rules

- **Base:** `/api/w/{ws}`. `{ws}` MUST match `WORKSPACE_ID`, and the existing `WS` dependency authenticates (session cookie or `Authorization: Bearer mck_…`).
- **Feature gate:** every route in this section except `GET /task-capabilities` returns `403 TASKS_DISABLED` while the feature is off (§3.1).
- **Protocol header:** every route except `/task-capabilities` and `/images` MUST receive `Meridian-Task-Protocol: <int>`.

  | Header value | Status | Code | Message |
  |---|---|---|---|
  | missing or not `^[0-9]{1,4}$` | 400 | `PROTOCOL_REQUIRED` | "send Meridian-Task-Protocol" |
  | below 1 | 426 | `PROTOCOL_TOO_OLD` | "this server needs task protocol 1 or newer: pip install -U meridian-compute" |
  | above 1 | 400 | `PROTOCOL_UNSUPPORTED` | "this server supports task protocol 1 only; upgrade the server or install an older meridian-compute" |
- **Request models:** JSON bodies are pydantic v2 models with `ConfigDict(extra="forbid", strict=True)`. There is no coercion (`"1"` is not `1`, and `true` is not an integer). A validation failure is `400 INVALID_REQUEST`, and the message lists field paths and reasons only, never values (reuse `validation._where`).
- **Errors** use the existing envelope `{"error": {"code", "message", "retryable", "server_time"}}` (`routes.error_response`). `retryable` is true only for `503` and `507`.
- **Ids in paths:** `{task_id}` MUST match `TASK_ID`, otherwise `404 NOT_FOUND`. A task from another workspace is `404 NOT_FOUND`, the same as a missing one.
- **No `text()` SQL.** Use SQLAlchemy expressions only.
- **Body limits:** `routes.BodyLimit.limit_for` gains these path rules, matched with a compiled regex before the existing rules:

  | Path regex | Limit |
  |---|---|
  | `^/api/w/ws_[0-9a-f]{20}/blobs/bundle/[0-9a-f]{64}$` | `MAX_BUNDLE_BYTES` |
  | `^/api/w/ws_[0-9a-f]{20}/blobs/payload/[0-9a-f]{64}$` | `MAX_PAYLOAD_BYTES` |
  | `^/control/v1/nodes/[^/]+/tasks/job_[0-9a-f]{20}/replicas/[0-9]{1,4}/result$` | `MAX_RESULT_BYTES` |

  The handlers count bytes again while they stream (defence in depth).
- **Edge:** `deploy/cloud/Caddyfile` on `:8441` adds a `request_body { max_size 21MB }` override for `path_regexp ^/api/w/[^/]+/blobs/bundle/`. Everything else keeps 8 MB.

### 2.3 `GET /api/w/{ws}/images`

- **Role:** viewer. No protocol header (the SDK may list images before any submit).
- **Response `200`:** `{"images": [Image…]}`. The images are static in phase 1 (§3.5), with fields `name` (`IMAGE_NAME`), `image` (`IMAGE_REF`), `python` (`"3.11"`), `cuda` (`"12.4"` or `""`), `description` (≤ 200 characters), `default` (bool; exactly one is true).

### 2.4 Blobs: `HEAD` and `PUT /api/w/{ws}/blobs/{kind}/{hex}`

- `{kind}` ∈ `bundle` | `payload`. Anything else is 404.
- `{hex}` MUST match `HEX_DIGEST`, otherwise `400 INVALID_DIGEST`.
- **Role:** operator.
- **Scope:** blobs are scoped to the workspace. A digest uploaded in workspace A does not exist for workspace B, so there is no cross-workspace dedupe and no existence oracle.

**HEAD**

| Status | Meaning | Headers |
|---|---|---|
| 200 | the blob exists in this workspace | `X-Meridian-Blob-Size: <int>` |
| 404 | it does not | — |

HEAD does not update `last_used_at`.

**PUT**

| Request item | Rule |
|---|---|
| `Content-Type` | MUST be `application/octet-stream`, otherwise `415 UNSUPPORTED_MEDIA_TYPE` |
| `Content-Length` | optional. If present and above the kind's cap: `413 TOO_LARGE` before reading. If present, the quota is checked before reading (§3.2) |
| body | raw bytes, 1 to cap (`MAX_BUNDLE_BYTES` or `MAX_PAYLOAD_BYTES`). Chunked bodies are allowed, and the cap is counted while streaming |

The handler reads `request.stream()`. It MUST NOT use `Body()` or `await request.body()`. Storage steps are in §3.2.

| Status | Code | When |
|---|---|---|
| 201 | — | stored. Body `{"kind", "digest": "sha256:<hex>", "size_bytes", "created": true}` |
| 200 | — | already present. The body was still streamed and verified, then discarded. `last_used_at` is updated. Body `{…, "created": false}` |
| 400 | `INVALID_DIGEST` | the path is not `HEX_DIGEST` |
| 400 | `EMPTY_BODY` | 0 bytes |
| 400 | `DIGEST_MISMATCH` | sha256 of the received bytes ≠ path. Nothing is stored |
| 409 | `STORAGE_QUOTA_EXCEEDED` | the workspace quota would be exceeded |
| 413 | `TOO_LARGE` | over the cap (declared or streamed) |
| 415 | `UNSUPPORTED_MEDIA_TYPE` | |
| 507 | `INSUFFICIENT_STORAGE` | free space on the store < `task_min_free_bytes`. Retryable |
| 401/403 | `UNAUTHENTICATED` / `FORBIDDEN` / `TASKS_DISABLED` | |

**Audit:** `task_blob_uploaded`, detail `"<kind> sha256:<hex> <size> bytes"`, only when `created` is true.

### 2.5 `POST /api/w/{ws}/tasks`: submit

**Choice:** a new endpoint that creates a `compute_jobs` row with `kind = "task"`.
**Rejected:** task fields on `POST /jobs`. That body is an untyped `dict` that also accepts `template`, `args`, `env`, `replicas`, `offer_id` and `rental_id`, every one of which must be impossible for a task. Separate endpoints keep the strict model, the idempotency header and the protocol header off the existing job path. Reusing the `Job` row reuses scheduling, quotas, usage, logs and cancel.

- **Role:** operator.
- **Headers:** `Meridian-Task-Protocol: 1` (§2.1). `Idempotency-Key: <IDEMPOTENCY_KEY>` is required: missing or malformed → `400 INVALID_IDEMPOTENCY_KEY`.
- **Request model `TaskSubmit`** (`extra="forbid"`, `strict=True`):

| Field | Type | Required | Rule |
|---|---|---|---|
| `name` | str | no | `validation.clean_text(…, 1, 120)`. Default: `entry.qualname`, cut to 120 characters |
| `image` | str | yes | `IMAGE_NAME` → resolved through the catalog (`400 UNKNOWN_IMAGE` if absent), **or** `IMAGE_REF` (≤ 512 characters) → used as given. Anything else: `400 INVALID_IMAGE` |
| `bundle` | str | yes | `DIGEST`. MUST exist as a `bundle` blob of this workspace, otherwise `400 BLOB_NOT_FOUND` (message: `"bundle sha256:… has not been uploaded to this workspace"`) |
| `payload` | str | yes | `DIGEST`. MUST exist as a `payload` blob of this workspace, otherwise `400 BLOB_NOT_FOUND` |
| `entry` | object | yes | `{"module": str, "qualname": str}`, `extra="forbid"`. Both MUST match `ENTRY_NAME`, otherwise `400 INVALID_ENTRY`. `module`'s first component MUST NOT be `__main__` (already excluded by the dunder rule) |
| `gpus` | int | yes | 0 to 16 |
| `min_vram_gb` | int | yes | 0 to 1024 |
| `timeout_seconds` | int | yes | 1 to 2,592,000 |
| `client_python` | str | no | `CLIENT_PYTHON`. Default `""`. Informational only: stored, passed to the runner, and never used in a CP decision |

- **Processing**, under `ComputeService._lock`, in this order:
  1. gate;
  2. protocol;
  3. idempotency key format;
  4. model;
  5. `request_digest = sha256(canonical_json(model.model_dump(mode="json")))`, where `canonical_json` is `json.dumps(…, sort_keys=True, separators=(",", ":"), ensure_ascii=False)`;
  6. idempotency lookup (below);
  7. image resolution;
  8. blob existence for both digests;
  9. `MAX_ACTIVE_JOBS` (`429 LIMIT`);
  10. GPU-hour quota (`409 QUOTA_EXCEEDED`, existing `_quota_hit`);
  11. insert `Job` (`kind="task"`, `image`=resolved `IMAGE_REF`, `args=TASK_ARGV`, `env={"HOME": "/tmp"}`, `replicas=1`, `gpus_per_replica=gpus`, `min_vram_bytes=min_vram_gb*1024**3`, `expose_port=False`, `timeout_seconds` = backstop §1.5, `rental_id=None`, `attributed_to` as in `submit_job`) and the `compute_tasks` row;
  12. update `last_used_at` on both blobs;
  13. audit `task_submitted`;
  14. `_place`;
  15. `_publish`;
  16. commit.
- **Idempotency:** `compute_tasks` has `UNIQUE(workspace_id, idempotency_key)`.

  | Situation | Response |
  |---|---|
  | key unseen | create; `201`, `Location: /api/w/{ws}/tasks/{id}` |
  | key seen, same `request_digest` | `200`, the existing task view, header `Idempotent-Replayed: true`. No new job. Audit `task_idempotent_replay` |
  | key seen, different `request_digest` | `409 IDEMPOTENCY_KEY_REUSED` ("this Idempotency-Key was used for a different request") |
  | concurrent insert loses the unique constraint | catch `IntegrityError`, roll back, then re-run the lookup → 200 or 409 as above |

  Keys live as long as the `compute_tasks` row; they are never deleted in phase 1.
- **Response:** the task view (§2.6).
- **Errors:** `400 INVALID_REQUEST | INVALID_IMAGE | UNKNOWN_IMAGE | BLOB_NOT_FOUND | INVALID_ENTRY | INVALID_IDEMPOTENCY_KEY | PROTOCOL_REQUIRED | PROTOCOL_UNSUPPORTED`, `401 UNAUTHENTICATED`, `403 FORBIDDEN | TASKS_DISABLED`, `409 IDEMPOTENCY_KEY_REUSED | QUOTA_EXCEEDED`, `413 TOO_LARGE` (body > `max_body_bytes`), `426 PROTOCOL_TOO_OLD`, `429 LIMIT`.
- **The existing `POST /jobs`** keeps rejecting `kind: "task"` (`_validate_job` allows only `job` and `service`). There MUST be a test for this.

### 2.6 `GET /api/w/{ws}/tasks/{task_id}`: status (the task view)

- **Role:** viewer.
- **Protocol header** required.
- **`404 NOT_FOUND`** if the job is absent, belongs to another workspace, or is not a task.

### 3.2 Blob store layout and writes

Paths come only from validated server values. `ws_id` matches `WORKSPACE_ID`; `hex` matches `HEX_DIGEST`; `job_id` matches `TASK_ID`. Every path helper asserts these patterns with `fullmatch` before joining, and asserts that `os.path.commonpath([root, p]) == root` afterwards.

```
<task_store_dir>/                      0700, created at startup
  tmp/<uuid4 hex>.part                 0600, in-progress uploads
  ws/<ws_id>/bundle/<hex>              0600
  ws/<ws_id>/payload/<hex>             0600
  ws/<ws_id>/result/<job_id>           0600
```

Directories are 0700, created with `os.makedirs(…, mode=0o700, exist_ok=True)`.

**Write algorithm** (blob PUT and result PUT):

1. `fd = os.open(tmp/<uuid4>.part, O_WRONLY|O_CREAT|O_EXCL|O_NOFOLLOW, 0o600)`.
2. Stream the chunks: update `hashlib.sha256` and a byte count, and abort with `413` past the cap (deleting the temp file). Check `shutil.disk_usage(task_store_dir).free < task_min_free_bytes` once before writing (`507`).
3. At the end, compare the digest. On a mismatch, delete the temp file → `400 DIGEST_MISMATCH`.
4. `os.fsync(fd)`, close, then `os.replace(tmp, final)`, then fsync the final directory. If `final` already exists, delete the temp file instead (same digest, same bytes).
5. Under `_lock`, upsert the DB row. If the DB write fails, the file is an orphan and GC removes it (§3.4).

**Quota:** `used = SUM(compute_task_blobs.size_bytes WHERE workspace_id) + SUM(compute_tasks.result_size WHERE workspace_id AND result_kind != '' AND result_deleted = false)`.

- A blob PUT is refused (`409 STORAGE_QUOTA_EXCEEDED`) when `used + incoming > task_storage_quota_bytes`. It is checked before streaming when `Content-Length` is known, and again under the lock before the row insert.
- Re-uploading an existing digest never counts twice.
- **Result uploads are never refused for quota** (losing a result is worse). They are bounded by `MAX_ACTIVE_JOBS × MAX_RESULT_BYTES` = 200 MiB per workspace, and they count toward `used`.
- Concurrent uploads may overshoot the quota by at most the in-flight uploads. This is documented, not prevented.

### 3.4 TTL and garbage collection

`ComputeService.gc_tasks(now)` runs from `tick()` at most every 600 s (an in-memory timestamp, which is enough on one replica). Each item runs in `_isolated`.

1. **Blobs:** delete the rows (and then the files) of `bundle`/`payload` blobs where `last_used_at < now − task_blob_ttl_hours` **and** no `compute_tasks` row whose job is not terminal references that digest in the same workspace.
2. **Results:** where `result_expires_at < now` and not `result_deleted`, delete the file and set `result_deleted = true`. The row stays (status, digests and sizes remain visible). `result_expires_at = job.finished_at + task_result_ttl_hours`, set when the job settles.
3. **Temp files:** delete `tmp/*.part` with mtime older than 1 h. The name MUST match `^[0-9a-f]{32}\.part$`; anything else is logged and left in place.
4. **Orphans:** for each `ws/<ws_id>/{bundle,payload}/<hex>` with no row and mtime older than 1 h, delete it. Names that do not match the patterns are logged, never deleted.
5. **Audit:** one `task_gc` event per workspace that lost something, detail `"blobs=<n> results=<m> bytes=<b>"`.

Deletion paths are built from row values (validated) only. Use `os.unlink` and never `shutil.rmtree` on the store.

### 4.2 Node-facing endpoints

**Common checks**, in this order. Every failure is answered with the contracts/v1 error envelope.

| # | Check | Failure |
|---|---|---|
| 1 | feature enabled | 403 `TASKS_DISABLED` |
| 2 | `verify_node_identity(node_id, client cert)` (always enforced: tasks require `require_mtls`) | 401/403 `NODE_NOT_AUTHORIZED` |

Step 5 is the only authorization for blob access: the path names a replica, never a digest. The CP looks the digest up from `compute_tasks`, so a node can only ever receive the bundle and payload of a replica that is currently assigned to it. This rules out cross-workspace access, since a replica is placed only on the job's own workspace's nodes (§4.3).

#### `GET /control/v1/nodes/{node_id}/tasks/{job_id}/replicas/{replica}/bundle`

#### `GET /control/v1/nodes/{node_id}/tasks/{job_id}/replicas/{replica}/payload`

- **Extra precondition:** the replica `phase ∈ {Pending, Starting, Running}`, otherwise 403 `NOT_ASSIGNED`.
- **`200`:** the body is streamed from the file in 64 KiB chunks (`StreamingResponse` over an open file, never read whole into memory). Headers:
  - `Content-Type: application/octet-stream`
  - `Content-Length: <size>`
  - `X-Meridian-Content-Digest: sha256:<hex>`
  - `Cache-Control: no-store`
- Updates the blob's `last_used_at`. Audit `task_blob_fetched`.
- **`410 BLOB_UNAVAILABLE`** if the file is missing (the node fails the replica with `BundleFetchFailed` and does not retry).

#### `PUT /control/v1/nodes/{node_id}/tasks/{job_id}/replicas/{replica}/result?kind=result|error`

- `kind` query param ∈ `result|error`, otherwise 400 `INVALID_REQUEST`.
- **Headers:** `Content-Type: application/octet-stream` (415 `UNSUPPORTED_MEDIA_TYPE`), `X-Meridian-Content-Digest: sha256:<hex>` (400 `INVALID_REQUEST` if missing or malformed), body 1 to `MAX_RESULT_BYTES` (413 `TOO_LARGE`; 0 bytes → 400 `INVALID_REQUEST`).
- **Extra precondition:** the job is not terminal and the replica phase is not terminal, otherwise 409 `TASK_FINISHED`.
- The body is written with the §3.2 algorithm to `ws/<ws_id>/result/<job_id>`. A digest mismatch → 400 `DIGEST_MISMATCH`, and nothing is stored.

| State | Response |
|---|---|
| no stored result | store; set `result_kind`, `result_digest`, `result_size`, `result_node_id`, `result_stored_at`; `201 {"stored": true}`; audit `task_result_stored` |
| stored, same kind and digest | `200 {"stored": false}` (agent retry after a restart) |
| stored, different | 409 `CONFLICT` ("a different result is already stored"); nothing changes |

## 5. Node behaviour (summary; the binding detail is `meridian-node/docs/COMPUTE_TASKS_NODE.md`)

### 5.1 Policy (root-owned config)

| Field | Default | Rule |
|---|---|---|
| `tasks_enabled` | `false` | requires `jobs_enabled` |
| `task_uid`, `task_gid` | `65534`, `65534` | 1 to 2,147,483,647; MUST NOT be 0 |
| `task_tmp_bytes` | `4294967296` (4 GiB) | ≥ 64 MiB. The tmpfs `/tmp` size; it counts against the container memory cap |
| `task_shm_bytes` | `1073741824` (1 GiB) | ≥ 64 MiB; `--shm-size` |
| `task_out_root` | `/var/lib/meridian-node-helper/task-out` | absolute, `MOUNT_PATH` grammar, MUST NOT be inside `state_dir` |

### 5.2 Layout

Built only from `job_key = f"{job_id}.{replica}"`, which MUST `fullmatch` the existing `JOB_ID` pattern.

```
<state_dir>/tasks/                 agent-owned, 0755
  <job_key>/                       0755
    bundle.tar.gz.part             0600, during download; deleted after extraction
    in/                            0755; bind-mounted read-only at /meridian/in
      bundle/code/…                dirs 0755, files 0644 (tar modes ignored)
      bundle/runner/meridian_runner.py   0644
      args.json                    0644 (the payload, verified)
      task.json                    0644 (the manifest, §6.2, written by the agent)
<task_out_root>/                   root, 0700 (helper's StateDirectory)
  <job_key>/                       tmpfs mountpoint: size=2 MiB, nr_inodes=16, uid=task_uid,
                                   gid=task_gid, mode=0700, nosuid, nodev, noexec;
                                   bind-mounted read-write at /meridian/out
```

### 5.3 Fetch

- The agent fetches on its launch executor, never on the tick thread.
- **Order:**
  1. check free space under `<state_dir>` (≥ 512 MiB, else `NodeDiskFull`);
  2. `rmtree` any leftover `<job_key>/`;
  3. download the bundle to `.part` (§4.2) with the session headers, enforcing `size_bytes` while streaming;
  4. verify sha256 and size against the **snapshot** values (the header must also match);
  5. extract (§5.4);
  6. download the payload to `in/args.json` the same way;
  7. write `task.json`;
  8. launch.
- **Retries:** network or 5xx errors are retried up to 5 times with 2, 4, 8, 16 and 32 s backoff, then `BundleFetchFailed`. `410`/`403` fail at once. A digest or size mismatch fails at once (`BundleDigestMismatch` / `PayloadDigestMismatch`). Nothing is launched after a failure.

### 5.4 Safe extraction

The agent, as a non-root user, extracts the hostile archive with least privilege. It never calls `extractall`.

- **Input:** gzip; `tarfile.open(fileobj=…, mode="r|gz")`. Any `tarfile`/`gzip`/`zlib` error → `UnsafeBundle`.
- **Member types:** only `REGTYPE`/`AREGTYPE` (regular) and `DIRTYPE`. Symlinks, hard links, character/block devices, FIFOs, contiguous and sparse files → reject.
- **Names:**
  - UTF-8 and ASCII; no NUL; no `\`; not absolute; no empty, `.` or `..` component;
  - each component matches `^[A-Za-z0-9_.@+=,-][A-Za-z0-9 _.@+=,-]{0,254}$`;
  - total ≤ `MAX_BUNDLE_PATH_BYTES`; depth ≤ `MAX_BUNDLE_DEPTH`;
  - the first component is `code` or `runner`. The only member under `runner` is the regular file `runner/meridian_runner.py`;
  - duplicates are rejected.
- **Caps:** members ≤ `MAX_BUNDLE_MEMBERS`. The sum of regular-file sizes ≤ `MAX_BUNDLE_UNPACKED_BYTES`, counted from the header **and** from the bytes actually written.
- **Writes:**
  - every directory is created by the agent (`mkdir`, mode 0755), and implicit parents are created too;
  - files are opened with `os.open(name, O_WRONLY|O_CREAT|O_EXCL|O_NOFOLLOW, 0o644, dir_fd=<parent fd>)`, where the parent fds are opened with `O_DIRECTORY|O_NOFOLLOW`;
  - tar modes, owners, mtimes and pax/xattr data are ignored.
- **Completeness:** `runner/meridian_runner.py` and `code/` MUST both exist at the end.
- **On any violation:** `rmtree(<job_key>/)`. The replica becomes `Failed/UnsafeBundle`, with a message that names the rule and the member index, never the member name. It is never retried.

### 5.5 Helper request: `launch_job` with a task

`JOB_FIELDS` gains `"task"`. The request is the existing one plus `"task": {"protocol": 1}`. The helper re-checks everything:

1. every existing `_validate_job` check (images, registries, devices, memory, env/args bounds);
2. `tasks_enabled`, else `POLICY_DENIED`;
3. `task` is an object with exactly the key `protocol`, whose value is in `[1]`;
4. `args == TASK_ARGV`; `port == 0`;
5. **in directory:** derived as `<state_dir>/tasks/<job_key>/in`, never taken from the request. `os.path.realpath` of it MUST equal the derived path; it MUST be a directory and not a symlink (`lstat`); it MUST be strictly inside `<state_dir>/tasks` by path components; it MUST match `MOUNT_PATH`. A missing `in/args.json`, `in/task.json` or `in/bundle/runner/meridian_runner.py` → `POLICY_DENIED`;
6. **out directory:** `<task_out_root>/<job_key>`. The helper creates it (`mkdir 0700`) and mounts a fresh tmpfs on it (`mount -t tmpfs -o size=2097152,nr_inodes=16,mode=0700,uid=<task_uid>,gid=<task_gid>,nosuid,nodev,noexec tmpfs -- <path>`, list-form `subprocess`). If it is already a mountpoint → `POLICY_DENIED` ("stale task output"). At-most-once launch means this cannot happen legitimately.

The Docker argv for a task, built by a pure function `task_run_args(spec) -> list[str]` that is unit-tested, adds to the job argv:

```
--user <task_uid>:<task_gid>  --read-only
--tmpfs /tmp:rw,nosuid,nodev,mode=1777,size=<task_tmp_bytes>
--shm-size <task_shm_bytes>
--mount type=bind,source=<in>,target=/meridian/in,readonly
--mount type=bind,source=<out>,target=/meridian/out
--label dev.meridian.task=1
--entrypoint python3
-- <image> -I -B /meridian/in/bundle/runner/meridian_runner.py
```

- **Entrypoint:** existing jobs append `args` to the image's `ENTRYPOINT`. A task MUST override it, or images with an entrypoint (tini in Jupyter, the API server in vLLM) would misbehave. `--entrypoint` takes `TASK_ARGV[0]`, and the remaining elements follow the image.
- **Container user:** `task_uid:task_gid` (65534, nobody), never the image's user.
- **Root filesystem:** read-only. The writable places are `/tmp` (tmpfs, memory-charged), `/dev/shm`, and `/meridian/out` (2 MiB tmpfs).
- **Network:** `meridian-jobs`, as for jobs (egress is not filtered; DESIGN §25.6).
- **Environment:** the existing env-file mechanism and GPU env.

**Out directory: choice and rejected alternative.**

- **Choice:** a host tmpfs per task, created and mounted by the helper and bind-mounted into the container. It has strict ownership through the mount options, a hard 2 MiB / 16-inode limit, no host disk exposure, and it survives container stop and agent or helper restarts.
- **Rejected:** copy-out from the stopped container (`docker cp`). It needs a writable in-image path (impossible with `--read-only` and a non-root user), puts a root-side parse of a container-produced tar stream on the boundary, and loses the result if the container is removed first.
- **Also rejected:** a plain host-directory bind, because it has no size limit.

### 5.6 Collection and upload

New helper read request `collect_task_result {"job_key", "runtime_id"}`. It is not journaled and is safe to repeat.

1. The container MUST be owned (`_require_owned`) and **not alive**, otherwise `POLICY_DENIED`.
2. `dfd = os.open(<task_out_root>/<job_key>, O_RDONLY|O_DIRECTORY|O_NOFOLLOW)`. `fstat`: must be a directory with `st_uid == task_uid`.
3. `names = os.listdir(dfd)`.
   - Empty → `{"kind": "none", "reason": "ResultMissing"}`.
   - Not exactly one name, or the name is not `result.json`/`error.json` → `{"kind": "none", "reason": "ResultInvalid"}`.
4. `fd = os.open(name, O_RDONLY|O_NOFOLLOW|O_NONBLOCK, dir_fd=dfd)`. An `ELOOP` (symlink) → `ResultInvalid`. `fstat`: `S_ISREG`, `st_nlink == 1`, `st_size ≤ MAX_RESULT_BYTES`, otherwise `ResultInvalid` / `ResultTooLarge`. Read at most `MAX_RESULT_BYTES + 1` bytes; more → `ResultTooLarge`. Zero bytes → `ResultInvalid`.
5. Return `{"kind": "result"|"error", "size": n, "digest": "sha256:<hex>", "data_b64": "<base64>"}`. **The helper never parses the JSON.**

**Agent sequence after the container exits** (exit seen via `inspect`):

| Step | `stage` | Action |
|---|---|---|
| 1 | `collecting` | helper `collect_task_result` |
| 2 | `uploading` | if `kind` is `result`/`error`: decode the base64, re-verify the sha256, `PUT …/result?kind=` on the executor |
| 3 | `done` | report the terminal phase |

Retry and outcome rules:

- **Upload retries:** network/5xx → retry on later ticks (the phase stays `Running`, stage `uploading`). `409 TASK_FINISHED` → stop retrying and report anyway. Other 4xx → `Failed/ResultUploadRejected`.
- **Terminal phase reported:**

| Collected | Exit code | Phase / reason |
|---|---|---|
| `kind == "result"` | 0 | `Succeeded/Completed` |
| `kind == "error"` | any | `Failed/NonZeroExit` (any exit code) |
| `kind == "result"` | ≠ 0 | `Failed/ResultInvalid` |
| `kind == "none"` | any | `Failed/<reason>` with the exit code |

- **Timeout and cancel:** the container is stopped, and the replica becomes `Failed/Timeout` or `Cancelled` with **no** collection.

### 5.7 Container, `/meridian/in`, `/meridian/out` (summary)

| Path in the container | Mode | Content |
|---|---|---|
| `/meridian/in` | read-only bind | `bundle/code/`, `bundle/runner/meridian_runner.py`, `args.json`, `task.json` |
| `/meridian/out` | read-write tmpfs, 2 MiB, 16 inodes, owner `task_uid`, 0700 | the runner writes exactly one of `result.json` / `error.json` |
| `/tmp` | tmpfs, `task_tmp_bytes` | scratch space; `HOME=/tmp` |
| `/` | read-only | the image |

### 5.8 Cleanup and crash recovery

- **Replica dropped from the snapshot** (`_forget`): stop and remove the container (existing). The helper's `remove` of a container labelled `dev.meridian.task=1` also unmounts (`umount -- <out>`) and `rmdir`s `<task_out_root>/<job_key>`, where `job_key` comes from the container's `dev.meridian.job` label after a `JOB_ID` fullmatch. The agent then `rmtree`s `<state_dir>/tasks/<job_key>/`.
- **Agent sweep each reconcile:** every entry under `<state_dir>/tasks/` whose name is not a desired key with state is removed (`shutil.rmtree`, which is symlink-safe; files with `unlink`).
- **Helper startup sweep:** for each entry under `<task_out_root>`:
  - unmount it if it is a mountpoint, then `rmdir` it, unless an owned container labelled with that job key exists;
  - names that fail `JOB_ID` are unmounted and removed too, since the root is helper-only.
- **Crash points:** §1.7.

## 6. Runner protocol

The runner is `meridian_compute/_runner.py` in the SDK. The SDK copies it into each bundle as `runner/meridian_runner.py`, so it always matches the SDK that built the bundle.

**Constraints on the runner:**

- stdlib only;
- source compatible with Python 3.8;
- no `eval`, `exec`, `compile`, `__import__` with user strings, `pickle`, `marshal`, `shelve`, `subprocess`, `os.system` or `ctypes`. An SDK test scans its AST for these names.

### 6.1 Command line and environment

**Command:** the CP sets `args = TASK_ARGV`. The node runs `--entrypoint python3 … -I -B /meridian/in/bundle/runner/meridian_runner.py`.

- `-I` isolates: `PYTHON*` env is ignored, there is no user site-packages, and the script directory is not on `sys.path`.
- `-B` writes no `.pyc` (the code tree is read-only).

The runner also accepts `--in DIR --out DIR` (defaults `/meridian/in`, `/meridian/out`) for tests only. The CP never sends them.

**Environment the runner may rely on:**

- `HOME=/tmp`;
- `MERIDIAN_JOB_ID`, `MERIDIAN_JOB_NAME`, `MERIDIAN_JOB_RANK`, `MERIDIAN_JOB_REPLICAS`;
- the GPU variables set by the helper.

There are no user environment variables in phase 1, and no credential of any kind.

### 6.2 `/meridian/in/task.json` (manifest; written by the agent)

The schema is `contracts/v1/task-manifest.schema.json`. The agent writes it with `json.dumps` from the validated snapshot fields; it is ≤ `MAX_MANIFEST_BYTES`.

```json
{"protocol": 1, "job_id": "job_0123456789abcdef0123",
 "entry": {"module": "train", "qualname": "fit"}, "client_python": "3.12"}
```

The runner validates it: exact keys, `protocol == 1`, `ENTRY_NAME` for both names plus the dunder rule, `CLIENT_PYTHON`.

**Choice:** the entry point travels in the snapshot and the manifest.
**Rejected:** putting it inside the bundle, which would make one bundle per function and duplicate a field the CP must validate anyway.

### 6.3 Execution steps (each failure writes `error.json` with the given `kind`)

1. Line-buffer stdout and stderr (`reconfigure(line_buffering=True)`).
2. Read `task.json` (≤ 4096 bytes), parse it strictly (§6.5 rules) and validate it → `protocol` on failure.
3. **Python check:** if `sys.version_info < (3, 8)`, the runner cannot run; Python exits non-zero and the node reports `ResultMissing`. If `client_python` is non-empty and differs from the runtime's `major.minor`, print one line to stderr: `meridian: warning: task built with Python X.Y, running on A.B`. Continue.
4. Read `args.json` (≤ `MAX_PAYLOAD_BYTES`) and decode it (§6.5) → `args` on failure.
5. `sys.path.insert(0, "/meridian/in/bundle/code")`; `os.chdir("/meridian/in/bundle/code")`.
6. Install the stub module (§6.4) as `sys.modules["meridian_compute"]`.
7. `importlib.import_module(entry.module)`. Any `BaseException` → `import`, with its traceback.
8. Resolve the qualname with `getattr` over the validated components. If the result is a stub `_StubTask` (identity check of `type(obj) is _StubTask`), take `obj.fn`. It MUST then be a `types.FunctionType`; otherwise → `import` ("entry is not a plain function").
9. Call `fn(*args, **kwargs)`. Any `BaseException`, including `SystemExit` and `KeyboardInterrupt` → `exception`.
10. Encode the return value (§6.5). `TypeError`/`ValueError` from the codec → `result_type`. Encoded size > `MAX_RESULT_BYTES` → `result_too_large`.
11. Write the file: `os.open("/meridian/out/.partial", O_WRONLY|O_CREAT|O_EXCL, 0o600)`, write, `fsync`, then `os.rename` to `result.json` or `error.json`. Exit `0` after `result.json` and `1` after `error.json`. If even writing `error.json` fails, print the reason to stderr and exit `3`.

**Size discipline for `error.json`:**

- `message` is cut to 8192 characters and `traceback` to 65536 characters (the tail is kept);
- the whole file is always ≤ `MAX_RESULT_BYTES`.

### 6.4 The `meridian_compute` stub inside the container

The SDK is not installed in the image, but user modules import it. The runner registers a stdlib stub so that the import works and decorators are inert. The stub exports:

- `Project(name)` with `.task(**kwargs)` → a decorator returning `_StubTask(fn)`. `_StubTask.__call__` runs `fn`, and `.run` / `.submit` raise `RuntimeError("calling a remote task from inside a task is not supported in phase 1")`;
- `Run`, whose methods raise the same error;
- every public exception class of §7.6, as plain `Exception` subclasses with the same names;
- `__version__ = "runner"`.

Importing any other name from it raises `ImportError` with the list of supported names.

### 6.5 JSON codec (protocol 1) and file schemas

**Encode** (the SDK for arguments, the runner for results):

| Python value | JSON |
|---|---|
| `None`, `bool`, `str` | as is |
| `int` | as is (any size) |
| finite `float` | as is |
| `nan`, `inf`, `-inf` | `{"$meridian": "float", "value": "nan"\|"inf"\|"-inf"}` |
| `list`, `tuple` | array (a tuple decodes as a list) |
| `dict` with all `str` keys | object. A key equal to `"$meridian"` → `TypeError("reserved key")` |
| `bytes`, `bytearray` | `{"$meridian": "bytes", "b64": "<standard base64>"}` |
| anything else (including numpy scalars and arrays, `set`, `datetime`, dataclasses) | `TypeError("<path>: <type> is not JSON-serialisable; convert it, e.g. float(x) or x.tolist()")` |

- Nesting depth ≤ 100, which also catches cycles.
- `json.dumps(…, ensure_ascii=False, allow_nan=False, separators=(",", ":"))`, UTF-8.

**Decode** (the runner for arguments, the SDK for results):

- `json.loads` with `parse_constant` raising on `NaN`/`Infinity`;
- `object_pairs_hook` rejecting duplicate keys and turning exactly-shaped tags back into values;
- an object with a `"$meridian"` key of any other shape → `ValueError`.

**Files** (each is a JSON object; unknown keys are rejected by the reader):

| File | Schema |
|---|---|
| `args.json` | `{"v": 1, "args": [<enc>…], "kwargs": {<identifier>: <enc>}}`. `kwargs` keys MUST satisfy `str.isidentifier()` and not be keywords |
| `result.json` | `{"v": 1, "value": <enc>}` |
| `error.json` | `{"v": 1, "kind": "exception"\|"import"\|"args"\|"protocol"\|"result_type"\|"result_too_large", "type": str ≤ 200, "module": str ≤ 200, "message": str ≤ 8192, "traceback": str ≤ 65536, "python": {"runtime": "3.11.9", "client": "3.12"\|""}}` |

`type`/`module` are the exception's `__qualname__` / `__module__` (for `result_*` and `protocol`, they are the runner's own `TypeError`/`ValueError`).

### 6.6 Exit codes

| Code | Meaning |
|---|---|
| 0 | `result.json` written |
| 1 | `error.json` written |
| 3 | neither could be written (stderr says why) |
| 2 | Python itself could not start the runner (for example, the file is missing) |
| 137 | SIGKILL (memory limit or forced stop) |
| other | killed or crashed outside the runner's control |

The node does not interpret exit codes beyond §5.6.

### 6.7 Required behaviour by case

| Case | Runner | Node | Client sees |
|---|---|---|---|
| Python minor version mismatch | warning on stderr; continue | — | `RemoteError` only if import or the call fails; its message includes both versions |
| Import error / missing qualname | `error.json` kind `import` | `Failed/NonZeroExit` | `RemoteError(kind="import")` |
| Function raised | kind `exception` | `Failed/NonZeroExit` | `RemoteError(kind="exception", type=…)` |
| Return value not serialisable | kind `result_type` | `Failed/NonZeroExit` | `RemoteError(kind="result_type")` |
| Result > 1 MiB | kind `result_too_large` | `Failed/NonZeroExit` | `RemoteError(kind="result_too_large")` |
| Timeout | (killed) | `Failed/Timeout`, no collection | `TaskTimeout` |
| Out of memory | (killed, 137) | `Failed/ResultMissing`, exit 137 | `TaskKilled` |
| User code writes junk into `/meridian/out` | — | `Failed/ResultInvalid` | `ResultMissing` |

## 7. SDK behaviour (`sdk/python`, distribution `meridian-compute`)

**Packaging:**

- `sdk/python/pyproject.toml`: hatchling, `name = "meridian-compute"`, `requires-python = ">=3.10"`, `dependencies = ["httpx>=0.27,<1"]`, `[project.scripts] meridian-compute = "meridian_compute.cli:main"`;
- src layout `sdk/python/src/meridian_compute/`;
- `__version__` is in `meridian_compute/__init__.py`, and hatch reads it from `pyproject.toml` `version` (static);
- the package includes `_runner.py`. The SDK reads it with `importlib.resources.files("meridian_compute").joinpath("_runner.py").read_bytes()`;
- ruff target `py310`, `mypy --strict`. CI runs the SDK tests on 3.10 to 3.13.

**Public API (phase 1):** `Project`, `Task`, `Run`, the exceptions of §7.6, `__version__`.

### 7.1 Bundle building

**Bundle root `R`:** the `sys.path` entry the task's top-level module was imported from.

- For a package `pkg.sub`, `R` is the parent of `pkg/`. For a single-file module `train.py`, `R` is its directory.
- **Refused** (`EntryPointError`):
  - a namespace package with more than one `__path__` entry;
  - a module file under any `site-packages` or `dist-packages` component ("the task must be defined in your project, not an installed package");
  - a module without `__file__`.

**Selection:**

- **Default:** the top-level package directory, or the single module file.
- **`include=[…]`** (on `@project.task`): extra paths relative to `R`, files or directories (recursive).
  - Each entry MUST be relative, without `..`, and MUST exist under `R` after `os.path.realpath`, otherwise `BundleError`.
  - Include adds to the default; it never removes.
- **Symlinks** are not followed. They are skipped with one warning each (`BundleWarning`) and listed in the dry-run as `skipped (symlink)`.
- **Non-regular files** are skipped silently.

**Excludes:**

- **Mandatory** (always excluded; `include` cannot override; matched on any path component or basename):
  - `.git`, `.hg`, `.svn`;
  - `.env`, `.env.*`, `.envrc`;
  - `*.pem`, `*.key`, `*.p12`, `*.pfx`, `*.jks`;
  - `id_rsa*`, `id_ed25519*`, `id_ecdsa*`, `id_dsa*`;
  - `.ssh`, `.aws`, `.gnupg`, `.docker`, `.kube`;
  - `.netrc`, `.pypirc`, `.npmrc`;
  - `.meridian-compute`, `credentials.json` inside a `.meridian-compute` directory.
- **Default** (excluded unless a path is named explicitly in `include`):
  - `__pycache__`, `*.pyc`, `*.pyo`;
  - any directory containing `pyvenv.cfg`, plus `.venv`, `venv`;
  - `.tox`, `.nox`, `.mypy_cache`, `.pytest_cache`, `.ruff_cache`, `.ipynb_checkpoints`;
  - `node_modules`, `*.egg-info`, `build`, `dist`, `.DS_Store`.
- **`.meridianignore`** in `R`: one `fnmatch` pattern per line, matched against the POSIX relative path and against the basename; a trailing `/` means directories only; `#` starts a comment; blank lines are ignored. A line starting with `!` → `BundleError("negation is not supported in phase 1")`.

**Archive layout and determinism** (the same tree gives the same bytes and digest on the same Python/zlib):

- **Members:** `code/<path relative to R>` for every selected file and every directory on the way, plus `runner/` and `runner/meridian_runner.py`.
- **Path grammar:** every relative path MUST satisfy the §5.4 grammar and caps (≤ 255 bytes, ≤ 32 components, ASCII component pattern), otherwise `BundleError` naming the path.
- **Ordering:** members are sorted by their full archive path as UTF-8 bytes; a directory entry precedes its contents.
- **`TarInfo` fields:** `mtime=0`, `uid=gid=0`, `uname=gname=""`, mode `0o755` for directories and `0o644` for files, `tarfile.PAX_FORMAT`, no extended attributes.
- **Gzip:** `gzip.GzipFile(filename="", mtime=0, compresslevel=9)`.
- A different zlib can change the bytes. That only costs a re-upload; it is never a correctness issue.

**Limits:** compressed > `MAX_BUNDLE_BYTES`, unpacked > `MAX_BUNDLE_UNPACKED_BYTES`, or members > `MAX_BUNDLE_MEMBERS` → `BundleError`. The message gives the total, the limit, and the 10 largest files with their sizes.

**Dry run:**

- `Task.bundle_preview()` returns `BundlePreview(files=[(path, size)], skipped=[(path, reason)], total_bytes, compressed_bytes, digest)` without any network call;
- `meridian-compute run --dry-run file.py::task` prints it.

**Upload:**

1. `HEAD /blobs/bundle/{hex}`.
2. If 404, `PUT`.
3. The digest is cached in-process by `(R, sorted (path, size, mtime_ns))`.

### 7.2 Entry-point rules

When the task is decorated, `@project.task` validates the function. Each refusal raises `EntryPointError` with a fix:

| Function | Result |
|---|---|
| `fn.__qualname__` contains `<lambda>` | refused ("use a def at module level") |
| `fn.__qualname__` contains `<locals>` (nested function) | refused |
| a method (the qualname has a dot and the parent is a class) | refused in phase 1 |
| `fn.__module__ == "__main__"` and `sys.modules["__main__"].__file__` exists | the module name becomes the file's stem. The stem MUST match `ENTRY_NAME` (one component), and `R` is the file's directory. The runner imports it under that name, so `if __name__ == "__main__":` blocks do not run remotely |
| `__main__` without `__file__` (REPL, `python -c`, Jupyter) | refused ("define the task in a .py file") |
| module or qualname fails `ENTRY_NAME` or the dunder rule | refused |

`gpu`, `timeout` and `image` are also validated at decoration time.

### 7.3 Task, Run and calls

- **`Project(name)`:** `name` matches `^[A-Za-z0-9][A-Za-z0-9._-]{0,63}$`. The job `name` sent is `f"{project}/{qualname}"[:120]`.
- **`@project.task(gpu=None, timeout=3600, image=None, include=())`** returns a `Task`:
  - `gpu`: §7.5;
  - `timeout`: an int number of seconds, or a string `^[0-9]+(s|m|h|d)$`, in range 1 to `TASK_TIMEOUT_MAX`;
  - `image`: `None` → the server's `default_image`, else `IMAGE_NAME` or `IMAGE_REF`;
  - `include`: §7.1.
- **`task(*a, **kw)`:** a plain local call, with no network and no encoding.
- **`task.submit(*a, **kw) -> Run`:**
  1. build and upload the bundle;
  2. encode the payload (§6.5), check it is ≤ `MAX_PAYLOAD_BYTES` (`SerializationError` otherwise), HEAD/PUT it;
  3. generate `Idempotency-Key = uuid.uuid4().hex`, once per `submit` call;
  4. `POST /tasks`, retrying with the **same key** on connection errors, timeouts, 502, 503 and 504, up to 3 times;
  5. return a `Run`.

  If the image is a catalog name whose `python` differs from the local `major.minor`, it emits `warnings.warn(PythonVersionWarning)` and continues.
- **`task.run(*a, **kw)`:** `submit(...).result(timeout=None)`. On `KeyboardInterrupt` while waiting, it sends a best-effort cancel (5 s timeout), prints `cancelled task <id>` to stderr, and re-raises.
- **`Run` methods:**

| Method | Behaviour |
|---|---|
| `.id` | the task id |
| `.status()` | returns a `TaskStatus` dataclass mirroring §2.6 |
| `.logs()` | returns `str` (`""` if `null` and not readable) |
| `.cancel()` | cancels the task |
| `.result(timeout=None)` | polls (§7.7) until terminal, then fetches and decodes the result (below) |
| `Run.attach(id)` | validates `TASK_ID` (`ValueError` otherwise) and returns a `Run` without a network call |

`.result()` details:

- After polling to a terminal state:
  - `outcome == "result"` → `GET /result`, verify `X-Meridian-Content-Digest` against the bytes and against the status view's `result.digest` (`RemoteProtocolError` on a mismatch), decode, and return `value`;
  - `"error"` → raise `RemoteError`;
  - `"infra"` → raise the `InfraError` subclass for `failure.reason`;
  - `"cancelled"` → `TaskCancelled`;
  - 410 → `ResultExpired`.
- The client checks the size of the received bytes against `MAX_RESULT_BYTES` before parsing.

### 7.4 JSON codec

This is §6.5, shared code in `meridian_compute/_codec.py`. The runner holds a byte-for-byte copy of the encode/decode functions, and a test asserts they are equal. Unsupported values raise `SerializationError(TypeError)`, which names the argument path (for example `kwargs["cfg"]["when"]`) and the type, never the value.

### 7.5 `gpu=` parsing (phase 1)

| Input | count | `min_vram_gb` |
|---|---|---|
| `None`, `0` | 0 | 0 |
| `int` N (1 to 16) | N | 0 |
| `"N"` (digits) | N | 0 |
| `"FAMILY"` | 1 | table |
| `"FAMILY:N"` | N | table |
| anything else | `ValueError` listing the accepted forms and the known families |

`FAMILY` is matched case-insensitively against a fixed table. The values are floor(GiB that NVML reports) for the smallest common SKU, so a matching GPU always qualifies:

| Family | GiB | Family | GiB |
|---|---|---|---|
| `T4` | 15 | `A100`, `A100-40GB` | 39 |
| `L4`, `A10`, `A10G` | 22 | `A100-80GB`, `H100` | 79 |
| `A40`, `L40`, `L40S` | 44 | `H200` | 139 |
| `V100` | 15 | `V100-32GB` | 31 |
| `RTX-3090`, `RTX-4090` | 23 | `RTX-A6000`, `RTX-6000-ADA` | 47 |

The family itself is **not** enforced in phase 1. The decorator emits `UserWarning("gpu family is mapped to ≥ N GiB of VRAM in phase 1; any GPU with that much memory may be used")` once per family.

### 7.6 Error hierarchy

```
MeridianError(Exception)
├── ConfigError                missing/invalid URL, workspace or key; bad credentials file permissions
├── EntryPointError            §7.2
├── BundleError                §7.1
├── SerializationError(TypeError)   arguments or result not encodable / payload too large
├── APIError                   .status .code .message; any non-2xx not mapped below
│   ├── AuthError              401, 403 FORBIDDEN, 403 RESULT_FORBIDDEN
│   ├── NotFoundError          404
│   ├── TasksDisabledError     403 TASKS_DISABLED
│   ├── ProtocolTooOldError    426 (message tells the user to upgrade)
│   └── QuotaError             409 QUOTA_EXCEEDED / STORAGE_QUOTA_EXCEEDED, 429 LIMIT
├── RemoteProtocolError        digest mismatch, malformed result or error file
├── RemoteError                .kind .type .module .message .traceback .python; str() shows the remote traceback
├── WaitTimeout(TimeoutError)  Run.result(timeout=) elapsed; the task keeps running
└── InfraError                 .reason .message .exit_code
    ├── TaskTimeout            Timeout
    ├── TaskKilled             Killed
    ├── NodeLost               NodeLost
    ├── StartDeadline          StartDeadline
    ├── LaunchFailed           PolicyDenied InvalidSpec LaunchFailed LaunchUncertain SpecChanged ContainerLost LocalAdmissionRejected NodeDiskFull
    ├── BundleRejected         BundleFetchFailed BundleDigestMismatch PayloadDigestMismatch UnsafeBundle
    ├── ResultMissing          ResultMissing ResultInvalid ResultTooLarge ResultUploadRejected
    ├── ResultExpired          410
    └── TaskCancelled          cancelled
```

An unknown `failure.reason` maps to `InfraError`. `RemoteError` never reconstructs or imports the remote exception class: phase 1 does no class reconstruction.

### 7.7 Polling, backoff and HTTP

- **Status polling:**
  - the first poll is immediate;
  - then the interval starts at 0.5 s and multiplies by 1.5 up to a 5 s cap, with ±10 % jitter;
  - `Retry-After` on 429/503 is honoured (capped at 60 s).
- **Transient errors** (connection errors, timeouts, 502/503/504) during polling are retried with the same backoff. After 10 consecutive failures, the last error is raised as `APIError`.
- **`httpx.Client`:** connect timeout 10 s, read timeout 60 s, write timeout 120 s, `follow_redirects=False`.
- **Headers:** `User-Agent: meridian-compute/<version>`, `Meridian-Task-Protocol: 1`.
- **URLs** are built only from validated ids (`TASK_ID`, `WORKSPACE_ID`, `HEX_DIGEST`) joined with fixed path literals. Query values go in `params=`.

### 7.8 Configuration and credentials

- **Sources**, per field, highest first:
  1. environment: `MERIDIAN_CLOUD_URL`, `MERIDIAN_WORKSPACE`, `MERIDIAN_API_KEY` (the same names as `meridian compute`);
  2. the credentials file.
- **File:** `MERIDIAN_COMPUTE_CREDENTIALS`, else `${XDG_CONFIG_HOME:-~/.config}/meridian-compute/credentials.json` (on Windows, `%APPDATA%\meridian-compute\credentials.json`).
  - Content: `{"version": 1, "url": str, "workspace": str, "api_key": str}`; unknown keys → `ConfigError`.
  - **Permissions (POSIX):** if the file mode has any group or other bit set, or the owner is not the current user, the SDK raises `ConfigError("chmod 600 <path>")` and does not read the key. The directory is created 0700 and the file is written 0600 via a temp file and `os.replace`.
- **Validation:**
  - `url` scheme `https`, or `http` only when the host is `localhost`, `127.0.0.1` or `::1`; no userinfo, query or fragment;
  - `workspace` matches `WORKSPACE_ID`;
  - `api_key` matches `^mck_[A-Za-z0-9_-]{20,128}$`.
- **The key is never printed.** `repr()` and `str()` of config and client objects show `mck_` plus the first 4 characters and `…`. Exceptions never include headers. There are no `httpx` logging hooks. `login` reads the key with `getpass`.

## 8. CLI (`meridian-compute`)

`meridian_compute/cli.py` uses `argparse`. Global flags are `--json` (machine output) and `--version`. Everything printed that came from the server or the node goes through the same `printable()` filter as `meridian/cli/compute.py` (copied, with no import from the gateway package).

| Command | Behaviour |
|---|---|
| `run TARGET [--arg K=V …] [--args-json JSON\|@FILE] [--detach] [--dry-run]` | `TARGET` is `path/to/file.py::task`, or `pkg.module::task` (resolved from the current directory as `R`). The CLI **imports the module locally** (this runs its top-level code, as `python file.py` would) and requires the attribute to be a `Task`. `--arg`: `K` matches `str.isidentifier()`; `V` is tried as strict JSON (§6.5 decode), and if that fails it is the raw string; repeated keys → usage error. `--args-json`: `{"args": [...], "kwargs": {...}}`, inline or `@file`. It is mutually exclusive with `--arg`. Default: `.run()`, printing the result value as JSON on stdout. `--detach`: `.submit()` and print the id. `--dry-run`: print the bundle preview |
| `result RUN` | wait, then print the value as JSON, or the remote traceback on stderr |
| `status RUN` | print the task view (human or `--json`) |
| `logs RUN [--follow]` | print `logs`; `--follow` polls every 3 s and prints only new text until the task is terminal |
| `cancel RUN` | cancel the task |
| `images` | list the catalog (§2.3) |
| `login [--url U] [--workspace W]` | prompt for the missing values (the key via `getpass`); verify with `GET /task-capabilities`; write the credentials file (§7.8); print `logged in to <ws> at <url> (key mck_abcd…)` |

**Exit codes:**

| Code | Meaning |
|---|---|
| 0 | success |
| 1 | `RemoteError` (user code failed) |
| 2 | usage/config/entry/bundle/serialisation error |
| 3 | `InfraError` or `APIError` |
| 4 | `WaitTimeout` |
| 130 | Ctrl-C |

**Relationship with `meridian compute` (the gateway CLI):**

- **Phase 1:** unchanged, and it does not know about tasks.
- **Later shim (not required now):** the gateway's `meridian compute task …` imports `meridian_compute.cli.main` when the package is installed and forwards `argv`; otherwise it prints `pip install meridian-compute`. The gateway would then declare `meridian-compute` as an optional extra. Both CLIs already read the same three environment variables.

## 10. Publishing (`.github/workflows/publish-sdk.yml`)

**Trigger:** `on: push: tags: ["sdk-v*"]` only. It does not collide with `release.yml` (`v*`).

**Permissions:**

- top-level `permissions: {}`;
- the `build` job has `contents: read`;
- the `publish` job has `id-token: write` only.

There is **no `environment:`** key anywhere.

**`build` job** (`ubuntu-latest`, Python 3.12):

1. Check out the repo.
2. **Version check:** `TAG_VERSION="${GITHUB_REF_NAME#sdk-v}"`; read `project.version` from `sdk/python/pyproject.toml` with `tomllib`; fail unless they are exactly equal.
3. `python -m pip install build twine`, then `python -m build sdk/python --outdir dist/`.
4. `twine check --strict dist/*`.
5. **Smoke test:** create a clean venv (`python -m venv /tmp/smoke`) and install **the wheel only** from `dist/` with `--no-index` plus httpx from PyPI (two steps: `pip install httpx`, then `pip install --no-index --no-deps dist/*.whl`). Then:
   - `meridian-compute --version` prints the tag version;
   - `python -I -c "import meridian_compute as m, importlib.resources as r; assert m.__version__ == '$TAG_VERSION'; assert r.files('meridian_compute').joinpath('_runner.py').is_file()"`;
   - `pip show meridian-compute` requires only `httpx`.
6. `actions/upload-artifact` the `dist/` directory.

**`publish` job** (`needs: build`):

1. `actions/download-artifact` into `dist/`.
2. `pypa/gh-action-pypi-publish@release/v1` with `packages-dir: dist/` and `attestations: false`.

Third-party actions SHOULD be pinned by commit SHA at implementation time.

**PyPI setup (manual, out of band):** add a trusted publisher for project `meridian-compute`: owner `IMV-IN`, repository `Meridian`, workflow `publish-sdk.yml`, environment **blank**. A pending publisher does not reserve the name.

**Nobody pushes an `sdk-v*` tag as part of phase 1 implementation.** The first release is a separate, deliberate step.

### 11.1 End-to-end round trip (automated)

2. Create a workspace, an operator member and an operator API key through the services.
3. **Node:**
   - `Agent` in `managed-host` mode, with `policy.management_enabled = jobs_enabled = tasks_enabled = true`, `job_allow_any_image = true`, `task_uid`/`task_gid` = the test user's ids, and `task_out_root` = a tmp dir;
   - `HttpTransport` with `client_cert_pem` = the enrolled certificate (the cert-header path that `test_mtls.py` uses);
   - `HelperRuntime` whose `send` calls an in-process `HelperServer`, whose backend is `FakeContainerBackend(run_tasks=True)`.
   - In that mode the fake backend's `launch_job` for a task spec runs `sys.executable -I -B <in>/bundle/runner/meridian_runner.py --in <in> --out <out>` synchronously (60 s timeout) as a subprocess, records its exit code, and marks the container exited.
   - The helper's tmpfs mount step is replaced by a plain `mkdir` when the helper policy flag `task_out_tmpfs = false` is set. That flag is test-only, defaults to true, and is not exposed in the node config.
4. **SDK:** `meridian_compute` with env `MERIDIAN_CLOUD_URL`, `MERIDIAN_WORKSPACE` and `MERIDIAN_API_KEY`. A temporary project directory holds `e2e_tasks.py`:

   ```python
   import meridian_compute as mc
   project = mc.Project("e2e")

   @project.task(gpu=0, timeout=60, image="pytorch-2.6")
   def add(a, b): return {"sum": a + b, "raw": b"\x00\xff", "inf": float("inf")}

   @project.task(gpu=0, timeout=60, image="pytorch-2.6")
   def boom(): raise ValueError("no")

   @project.task(gpu=0, timeout=60, image="pytorch-2.6")
   def bad(): return object()
   ```

**The test drives** `agent.tick()` and `compute.tick()` alternately, in a helper loop with a 30 s bound, while `Run.result()` runs in a thread.

**Assertions:**

| Case | Expected |
|---|---|
| `add.run(2, 3)` | `{"sum": 5, "raw": b"\x00\xff", "inf": inf}`; task `succeeded`; the result digest on the CP equals the bytes the runner wrote |
| `boom.run()` | `RemoteError` with `kind == "exception"`, `type == "ValueError"`, and `"no"` in `message` |
| `bad.run()` | `RemoteError(kind="result_type")` |
| idempotency | a second `POST /tasks` with the same key and body returns the same id |
| viewer key | `GET /result` is 403; the task view's `logs` is `null` |
| GC | after advancing the clock past the TTLs, the files and rows are gone, and `/result` is 410 |

**Acceptance:** S1 to S20, N1 to N11 and K1 to K10 pass; the e2e passes; `ruff` and `mypy` pass in all three code bases; `test_migrations.py` covers the new revision.

### 11.2 Manual validation on a real GPU node

1. **CP:** set `MERIDIAN_CONTROL_CLOUD=1`, `MERIDIAN_CONTROL_SELF_HOSTED=1` (or `MERIDIAN_CONTROL_CODE_BUNDLES=1`) and `MERIDIAN_CONTROL_REQUIRE_MTLS=1`, behind the mTLS edge (the Caddyfile pattern, `:8442`). Check that `GET /api/w/<ws>/task-capabilities` shows `enabled: true`.

3. **Laptop:**
   - `pip install ./sdk/python`;
   - `meridian-compute login`;
   - `meridian-compute images`;
   - write `gpu_hello.py`:

     ```python
     @project.task(gpu=1, timeout=600)
     def hello():
         import torch
         return torch.cuda.get_device_name(0)
     ```

   - `meridian-compute run gpu_hello.py::hello` → prints the GPU name.
4. **Exception:** a task that raises → exit code 1 and the remote traceback.

7. **Visibility:** a viewer API key gets 403 on `meridian-compute result <id>`.
8. **Restart:** `systemctl restart meridian-node` while a 2-minute task runs → the task still succeeds.
9. **Record:** the measured cold-start time (submit to `running`, warm image) and the result in `docs/validation/`.

## 12. Out of scope (phase 1) and open questions

### 12.1 Not in phase 1

- Partner or marketplace placement; rentals.
- Dependency installation, lockfiles, `Stack`.
- Fan-out or `.map()`.
- Volumes and secrets.
- Streaming logs; logs beyond the 8 KiB tail.
- Pickle or cloudpickle anywhere; numpy or other tagged types beyond bytes and non-finite floats.
- Exception class reconstruction.
- Task retries; multi-replica tasks.
- Calling a task from inside a task.
- Methods and classes as tasks; async functions (an `async def` entry is refused by `EntryPointError` in phase 1).
- An async client.
- Per-task CPU or memory requests (the node default memory cap applies).
- GPU family enforcement.
- Workspace-editable image catalog; `images add|resolve`.
- Sealed or encrypted bundles and results; a hosted-cloud default of ON.
- A dedicated task list endpoint (`GET /jobs` lists tasks as `kind: "task"`).
- The `meridian compute` shim; TestPyPI publishing; a console UI for tasks beyond what `/jobs` shows.

### 12.2 Open questions (with the default this spec adopts)

| # | Question | Default adopted |
|---|---|---|
| Q1 | Who may read results and task logs: any operator, or only the submitter plus admins? | The submitter plus admins (§2.7). Revisit if labs want shared results |
| Q2 | How does the CP know it is "standalone"? | The new `MERIDIAN_CONTROL_SELF_HOSTED` (default false), so tasks are off unless declared or the flag is set explicitly |
| Q3 | Exact Python and CUDA versions of the catalog images | Expected 3.11/3.12; MUST be verified by running the image when `images.py` is written |
| Q4 | Bundle dedupe scope | Per workspace (no cross-tenant existence oracle) |
| Q5 | Does Ctrl-C during `.run()` cancel the task? | Yes, best-effort; `.submit().result()` does not cancel |
| Q6 | Retention | Results 7 days after finish; bundles and payloads 24 h after last use; idempotency keys forever (with the row) |
| Q7 | Container identity | `65534:65534` for every task; per-workspace uids with volumes in phase 3 |
| Q8 | Read-only root filesystem for tasks | Yes, with a 4 GiB `/tmp` tmpfs charged to the memory cap; jobs and services stay as they are |
| Q9 | A per-task memory request | None; node `job_memory_default_bytes` (32 GiB) applies |
| Q10 | Fetch retry budget | 5 attempts (2 to 32 s backoff), within the 30-minute start deadline |
